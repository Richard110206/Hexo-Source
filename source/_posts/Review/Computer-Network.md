## 第1章 计算机网络绪论

### 1.1 计算机网络的定义

**计算机网络**是指将地理位置不同的具有独立功能的多台计算机及其外部设备，通过通信线路连接起来，在网络操作系统、网络管理软件及网络通信协议的管理和协调下，实现**资源共享**和信息传递的计算机系统。

{% note info %}
**定义三要素：**
1. **自主计算机**——具有联网能力的独立计算机（独立配置、独立工作、自由进退）
2. **规范互连**——任意两两之间物理相通、逻辑沟通
3. **共享资源**——彼此互享、公共分享（计算能力、存储空间、信道带宽、信息数据）
{% endnote %}

### 1.2 网络的分类

#### 按作用范围分类

| 类型 | 缩写 | 范围 |
|------|------|------|
| 广域网 | WAN | 几十到几千公里 |
| 城域网 | MAN | 约5~50公里 |
| 局域网 | LAN | 约1公里左右 |
| 个人区域网 | PAN | 约10米 |

#### 按拓扑结构分类

星形、环形、总线形、树形、网形

### 1.3 计算机网络的功能

**外在功能（服务功能）：** 资源共享、信息交换、分布式处理、协同工作、提高可靠性

**内在功能（7个基本方面）：**
1. 节点的物理连接及信号传输
2. 节点间数据的可靠传输
3. 多传输路径下的路径标识及选择
4. 端到端的数据保障
5. 多任务环境下端到端进程的识别和数据交付
6. 不同背景用户信息数据的统一理解
7. 信息数据的呈现和应用规则的统一

### 1.4 网络性能指标

{% note warning %}
**高频考点：时延计算、带宽与吞吐量、信道利用率**

**时延（delay/latency）= 发送时延 + 传播时延 + 处理时延 + 排队时延**
{% endnote %}

{% note default %}
**【作业题】** 收发两端之间的传输距离为1000km，信号在媒体上的传播速率为2×10⁸ m/s。试计算以下情况的发送时延和传播时延：

（1）数据长度为10⁷ bit，数据发送速率为100kbit/s。

（2）数据长度为10³ bit，数据发送速率为1Gbit/s。

（3）从以上计算结果可得出什么结论？

**解答：**

（1）发送时延 = 数据长度/发送速率 = 10⁷/(100×10³) = 100s

传播时延 = 传输距离/传播速率 = 1000×10³/(2×10⁸) = 5×10⁻³s = 5ms

（2）发送时延 = 10³/(10⁹) = 10⁻⁶s = 1μs

传播时延 = 1000×10³/(2×10⁸) = 5×10⁻³s = 5ms

（3）电磁波在同种媒体上传播距离不变时传播时延相同，与数据的发送速率无关。但数据长度越长，发送速率越慢则需要的发送时延越长。
{% endnote %}

{% note default %}
**【作业题】** 试计算一个包括5段链路的运输连接的单程端到端时延（以ms为单位）。5段链路中有2段是卫星链路，有3段是广域网链路。每条卫星链路由上行链路和下行链路组成，传播时延之和为250ms。每个广域网范围为1500km，传播时延按150000km/s计算。各数据链路速率为48kbits/s，帧长为960bits。

**解答：**

（1）卫星链路单程传播时延 = 250ms，两段卫星 = 250×2 = **500ms**

（2）广域网单程传播时延 = 1500/150000 = 10×10⁻³s = **10ms**，三段广域网 = 10×3 = **30ms**

（3）每段链路发送时延 = 960/(48×10³) = 0.02s = **20ms**，五段链路 = 20×5 = **100ms**

（4）总时延 = 500 + 30 + 100 = **630ms**
{% endnote %}

| 指标 | 定义 |
|------|------|
| **速率** | 数据传送速率（额定数据率） |
| **带宽** | 单位时间网络中某信道能通过的最高数据率 |
| **吞吐量** | 单位时间通过某个网络（信道、接口）的数据量 |
| **发送时延** | 主机或路由器发送数据帧所需时间 = 数据帧长度/信道带宽 |
| **传播时延** | 电磁波在信道中传播一定距离所需时间 = 信道长度/电磁波传播速率 |
| **处理时延** | 主机或路由器处理分组（分析首部、查找路由等）花费的时间 |
| **排队时延** | 分组在路由器输入输出队列中排队等待的时间 |
| **时延带宽积** = 传播时延 × 带宽 | 表示链路可容纳的最大比特数 |
| **往返时延 RTT** | 从发送方发送数据到收到确认所经历的总时间 |
| **信道利用率** | 信道有数据通过的时间百分比 |

**时延与利用率关系：** $D = D_0 / (1 - U)$，利用率U增大时，时延D迅速增大。

### 1.5 三种交换方式

{% note primary %}
**重点：三种交换方式的对比、电路交换三个阶段**

**1. 电路交换：** 建立连接 → 数据传输 → 释放连接
- 通信时延小、有序、无冲突、控制简单
- 建立连接时间长、线路独占、灵活性差

**2. 报文交换：** 存储转发方式，无需建立连接
- 动态分配线路、利用率高、提供多目标服务
- 转发时延大、需要较大缓存空间

**3. 分组交换：** 存储转发，限制数据块上限
- 无建立时延、利用率高、加速传输、适合突发式数据通信
- 存在传输时延、需额外信息量、可能失序/丢失/重复
{% endnote %}

{% note default %}
**【作业题】** 长度为100字节的应用层数据交给运输层传送，需加上20字节的TCP首部，再交给网络层传送，继续加上20字节的IP首部，最后交给数据链路层的以太网传送，以太网的首部和尾部共18字节。试求数据的传输效率。

**解答：** 网络传输数据时从应用层到物理层，除物理层外的每一层都需要加上该层的首部结构（数据链路层可能还需要加上校验尾部结构）。

需要传送的数据量 = 100字节，实际传送的数据量 = 100+20+20+18 = 158字节

传输效率 = 100/158 ≈ **63.3%**
{% endnote %}

### 1.6 OSI与TCP/IP体系结构

**OSI七层（从下到上）：** 物理层 → 数据链路层 → 网络层 → 运输层 → 会话层 → 表示层 → 应用层

**TCP/IP四层：** 网络接口层 → 网际层(IP) → 运输层(TCP/UDP) → 应用层

**五层协议体系结构（折中方案）：**

| 层次 | 名称 | 功能概述 | 数据单位 |
|------|------|----------|----------|
| 5 | 应用层 | 通过应用进程间交互完成特定网络应用 | 报文 |
| 4 | 运输层 | 为两台主机进程间通信提供通用数据传输服务 | TCP报文段/UDP用户数据报 |
| 3 | 网络层 | 为分组交换网上不同主机提供通信服务，选择路由 | IP数据报 |
| 2 | 数据链路层 | 相邻结点间传送帧，封装成帧、差错检测 | 帧 |
| 1 | 物理层 | 在物理媒体上传送比特流 | 比特 |

{% note info %}
**协议三要素：** 语法（表示规则）、语义（内容）、时序（作用顺序）
- 协议是水平的（对等实体之间）
- 服务是垂直的（上下层之间）
- 接口是同一结点相邻两层间交换信息的连接点（SAP）
{% endnote %}

{% note info %}
**C/S方式与P2P方式：**
- C/S（客户/服务器）：主动-被动模式，客户请求，服务器提供服务
- P2P（对等连接）：双方都是客户和服务器，本质仍是C/S方式
{% endnote %}

## 第2章 物理层

### 2.1 物理层的基本概念

物理层要尽可能屏蔽掉物理设备和传输媒体、通信手段的不同，使数据链路层感觉不到这些差异。主要任务是确定与传输媒体接口的**机械**、**电气**、**功能**和**规程**特性。

### 2.2 数据通信理论基础

{% note warning %}
**必考点：奈氏准则和香农公式**

**奈氏准则（理想低通信道）：** $C = 2W \log_2 V$ (bit/s)
- W = 理想低通信道带宽(Hz)
- V = 码元种类数
- 给定带宽下，码元传输速率有上限，否则码间串扰

**香农公式（有噪声信道）：** $C = W \log_2(1 + S/N)$ (bit/s)
- W = 信道带宽(Hz)
- S/N = 信噪比（用分贝表示：信噪比dB = $10 \log_{10}(S/N)$）
- 带宽或信噪比越大，极限传输速率越高
- 只要低于极限速率，一定能找到无差错传输方法
{% endnote %}

{% note default %}
**【作业题】** 假定信道带宽为3100Hz，最大信息传输速率为35kbit/s，请用香农公式计算：

（1）若想使最大信息传输速率增加60%，问信噪比S/N应增大到多少倍？

（2）如果在（1）基础上将信噪比S/N再增大到10倍，问最大信息速率能否再增加20%？

**解答：**

（1）$C_1 = 35 \text{ kbit/s}$，由 $C = W\log_2(1+S/N)$：$S/N_1 = 2^{C_1/W}-1 \approx 2502.97$

$C_2 = 1.6 \times C_1 = 56 \text{ kbit/s}$，$S/N_2 = 2^{C_2/W}-1 \approx 273275.14$

**S/N应增大到约109倍**（$273275.14/2502.97 \approx 109.18$）

（2）$S/N_3 = 10 \times S/N_2$，$C_3 = W\log_2(1+S/N_3)$

增加比例约7.7%，**不能**再增加20%。
{% endnote %}

### 2.3 基带编码方式

| 编码方式 | 特点 |
|----------|------|
| **不归零制(NRZ)** | 正电平=1，负电平=0，直接转换不经零电平。无自同步能力 |
| **归零制(RZ)** | 正脉冲=1，负脉冲=0，脉冲间经过零态 |
| **曼彻斯特编码** | 位中间上跳变=0，下跳变=1（也可反过来）。有自同步能力，频带宽度加倍 |
| **差分曼彻斯特编码** | 每位中心始终有跳变；位开始边界有跳变=0，无跳变=1。有自同步能力 |

{% note default %}
**【作业题】** （1）画出数字信息011101001的曼彻斯特编码和差分曼彻斯特编码。

（2）10Mb/s以太网的码元传输速率是多少？

**解答：**

（1）曼彻斯特编码：每个码元中心有跳变，高→低=1，低→高=0。

差分曼彻斯特编码：码元前沿有跳变=0，无跳变=1。

（2）波特率 = 数据率 × 2 = **20 MBaud**（曼彻斯特编码每个码元用两个信号周期）
{% endnote %}

### 2.4 信道复用技术

{% note primary %}
**重点：四种复用方式的原理与区别**

| 复用方式 | 原理 |
|----------|------|
| **频分复用FDM** | 将总带宽分割成若干子信道，每路信号占用不同频段 |
| **时分复用TDM** | 将时间划分为等长TDM帧，每用户占用固定时隙。可能造成线路浪费 |
| **统计时分复用STDM** | 按需动态分配时隙，提高利用率 |
| **波分复用WDM** | 光的频分复用，一根光纤同时传输多个不同波长的光载波信号 |
| **码分复用CDM(CDMA)** | 各用户使用不同码型，同一时间使用同一频带，码片序列必须相互正交 |
{% endnote %}

{% note warning %}
**CDMA要点：**

**规则1——编码规则：**
- 每个站分配唯一的 m bit 码片序列，各站码片必须**互相正交**（规格化内积=0）
- 发送比特1 → 发送码片序列本身
- 发送比特0 → 发送码片序列的**反码**（每个比特取反）
- 不发送 → 不发送任何信号（即全0）
- 例如S站码片为00011011 → 向量(-1,-1,-1,+1,+1,-1,+1,+1)

**规则2——空中叠加规则：**
- 所有站点共用同一信道，多个站同时发送时，空中信号是**线性叠加**
- 数学上就是对应对应位置数字直接相加（不是异或，是代数加法）
- 例：A发送(+1,+1)且B发送(-1,+1)，则叠加后空中信号 = **(0,+2)**

**规则3——解码规则（规格化内积）：**
- 将收到的叠加序列与某站码片序列做**规格化内积**（点积 ÷ m）
- 自己和自己的内积 = **+1**（发送了比特1）
- 自己和反码的内积 = **-1**（发送了比特0）
- 与正交的其他站内积 = **0**（未发送）
{% endnote %}

{% note default %}
**【作业题】** 假设4个站的码片序列分别为：

A: (-1,-1,-1,+1,+1,-1,+1,+1)　B: (-1,-1,+1,-1,+1,+1,+1,-1)

C: (-1,+1,-1,+1,+1,+1,-1,+1)　D: (-1,+1,-1,-1,-1,-1,+1,-1)

（1）现收到码片序列：(-1,+1,-3,+1,-1,-3,+1,+1)。问哪个站发送了什么数据？

（2）假定A、B和C站同时发送比特0，请计算发送结果产生的码片序列。

**解答：**

（1）将收到的序列与各站码片做规格化内积（点积 ÷ 8）：

A: 1-1+3+1-1+3+1+1 = 8 → 8/8 = **+1 → 发送比特1**

B: 1-1-3-1-1-3+1-1 = -8 → -8/8 = **-1 → 发送比特0**

C: 1+1+3+1-1-3-1+1 = 2 → 2/8 ≠ ±1 → **未发送**

D: 1+1+3-1+1+3+1-1 = 8 → 8/8 = **+1 → 发送比特1**

（2）发送比特0即发反码，三个站反码对应位置直接相加（线性叠加）：

A反码: (+1,+1,+1,-1,-1,+1,-1,-1)

B反码: (+1,+1,-1,+1,-1,-1,-1,+1)

C反码: (+1,-1,+1,+1,+1,+1,+1,-1)

空中信号 = **(+3,+1,+1,-1,-3,+1,-1,+1)**
{% endnote %}

### 2.5 常用传输媒体

| 媒体 | 特点 |
|------|------|
| **双绞线** | 两根绝缘金属导线绞合，减少干扰，价格便宜，性能不错（有屏蔽STP和无屏蔽UTP） |
| **同轴电缆** | 内芯导体+外屏蔽层，固定特性阻抗，抗干扰性能好，价格较高 |
| **光纤** | 传输损耗小，抗电磁干扰，无串扰，保密性高，容量大，体积小重量轻（单模/多模，三个波段850nm/1300nm/1550nm） |
| **无线电** | 适合远距离，抗干扰能力差 |
| **微波** | 直线传播（地面接力、卫星通信） |

{% note default %}
**【作业题】** 试计算工作在1200nm到1400nm之间以及工作在1400nm到1600nm之间的光波的频带宽度。假定光在光纤中的传播速率为2×10⁸ m/s。

**解答：** $\nu = c/\lambda$

- $\nu_1$ (1200nm) = 166.67 THz，$\nu_2$ (1400nm) = 142.86 THz
- **1200~1400nm频带宽度 = 23.81 THz**
- $\nu_3$ (1600nm) = 125 THz
- **1400~1600nm频带宽度 = 17.86 THz**
{% endnote %}

{% note default %}
**【真题】不归零制和曼彻斯特编码画图：**

给定二进制序列 1100101：

- **不归零制(NRZ)：** 高电平为1，低电平为0，直接在1和0之间切换
- **曼彻斯特编码：** 每个位中间有跳变。若定义上跳变=0，下跳变=1：
  - 1→中间下跳，0→中间上跳，1→中间下跳，0→中间上跳，0→中间上跳，1→中间下跳

**【真题】带宽为4kHz，信噪比为30dB的信道，最大数据传输速率？**

信噪比30dB → $S/N = 10^{30/10} = 1000$

$C = W \log_2(1+S/N) = 4000 \times \log_2(1001) \approx 4000 \times 9.97 \approx 39880$ bit/s ≈ 40 kbit/s
{% endnote %}

## 第3章 数据链路层

### 3.1 数据链路层的三个基本问题

1. **封装成帧：** 在数据前后添加首部和尾部，进行帧定界（SOH开始，EOT结束）
2. **透明传输：** 不管什么字符都能放在帧中传输。字节填充：在控制字符前插入转义字符ESC
3. **差错检测：** 循环冗余校验CRC

### 3.2 CRC循环冗余校验

{% note danger %}
**必考点：CRC计算（几乎每年都考）**

**计算步骤：**
1. 设待发送数据为M（k位），生成多项式为P（n+1位，对应n位冗余码）
2. 被除数 = M后面加n个0（即 $M \times 2^n$）
3. 被除数对P进行**模2除法**（异或运算），得到余数R（n位）
4. 发送的数据 = M拼接R（即 $M \times 2^n + R$）

**接收端：** 用相同除数P对接收数据做模2除法，余数为0则无差错，否则有差错。

**模2运算规则：** 加法和减法相同——相同为0，相异为1
{% endnote %}


实际发送：101010101**111**
{% endnote %}

{% note default %}
**【作业题】** 假设要发送的数据为1101011011。CRC的生成多项式为P(X) = X⁴+X+1：

（1）试求应添加在数据后面的CRC余码。

（2）如果数据在传输过程中最后一个1变成了0，问接收端能否发现？

（3）若数据在传输过程中最后两个1变成了两个0，问接收端能否发现？

（4）采用CRC检验后，数据在数据链路层是否就变成了可靠的传输？

**解答：** 根据生成多项式知除数 = 10011（5位），余数应为4位：

（1）被除数 = 1101011011 **0000**（后加4个0），对10011做模2除法得余数 = **1110**，实际发送：**11010110111110**

（2）接收到的数据变为11010110101110，模2除10011得余数=0011≠0，**能发现错误**（但不知道哪个比特位出错）

（3）接收到的数据变为11010110001110，模2除10011得余数=0101≠0，**能发现错误**（但不知道哪个比特位出错）

（4）**不是可靠的传输**。CRC只能检测比特差错，但传输错误还包括失序、丢失等。数据链路层缺少序号和重传机制，失序时无法重组，丢失时无法重传。
{% endnote %}

### 3.3 PPP协议

**PPP特点：** 简单、封装成帧、透明传输、多种网络协议、面向字节、提供差错检测（不纠错）、全双工

**PPP帧格式：**
- 标志字段 F = 7E（同步）| 地址 A = FF | 控制 C = 03 | 协议(2字节) | 信息部分 | FCS(4字节) | 标志 7E

**字节填充：** 信息中7E→7D5E，7D→7D5D，小于0x20的字符前面加7D

**零比特填充：** 同步传输时，连续5个1后填入一个0

{% note default %}
**【作业题】** （1）一个PPP帧的数据部分是7D5EFE277D5D7D5D657D5E（十六进制）。问数据部分出现了几个帧定界符，几个转义符，真正的数据是什么？

（2）PPP协议使用同步传输传送比特串0110111111111100，经零比特填充后变成怎样？

（3）接收端收到PPP帧的数据部分是0001110111110111110110，删除零比特后变成怎样？

**解答：**

（1）帧定界符7E，转义符7D。接收端遇到0x7D就丢弃，将其后字符+0x20：

- 7D→5E → **7E**（帧定界符）
- 7D→5D → **7D**（转义符）
- 7D→5D → **7D**（转义符）
- 7D→5E → **7E**（帧定界符）

共出现 **4个转义符**（0x7D），**2个帧定界符**和**2个转义符**在真实数据中。

真正数据 = **7EFE277D7D657E**

（2）零比特填充：发现连续5个1后填入一个0。

01101111**1**111111**1**00 → **011011111011111000**

（3）接收端删除填充位：连续5个1后面的0删除，连续5个1后面的1是帧定界符不删。

000111011111**0**11111**0**110 → **00011101111111111110**
{% endnote %}

### 3.4 CSMA/CD协议

{% note danger %}
**必考点：CSMA/CD算法步骤、截断二进制指数退避算法**

**CSMA/CD要点：** 载波监听多点接入/碰撞检测 → "先听后发，边听边发，冲突停发，随机重发"

**算法步骤：**
1. 准备发送：适配器从网络层获得分组，组成以太网帧放入缓存
2. 检测信道：若忙则等待；若空闲并在96bit时间内保持空闲，发送帧
3. 边发送边检测：
   - 未检测到碰撞 → 发送成功，回到步骤1
   - 检测到碰撞 → 停止发送，发送人为干扰信号（32/48bit），执行退避算法
4. 重传16次仍不成功 → 丢弃帧并向上报错
{% endnote %}

{% note warning %}
**截断二进制指数退避算法：**
- 基本退避时间 = 争用期 2τ（10Mbit/s以太网为51.2μs）
- $k = \min(重传次数, 10)$
- 从集合 $\{0, 1, 2, ..., 2^k - 1\}$ 中随机取r
- 重传退避时间 = $r \times 2\tau$ = $r \times 51.2\mu s$
- 重传16次不成功则放弃

**争用期（碰撞窗口）：** 端到端往返时延2τ = 51.2μs
- 以太网最短帧长 = 64字节（512bit），争用期内可发送512bit
- 帧间最小间隔 = 9.6μs = 96bit时间

**信道利用率：** 参数 $a = \tau/T_0$（单程时延/帧发送时间），a越小利用率越高
- 极限利用率：$S_{max} = T_0/(T_0 + \tau) = 1/(1+a)$
- 以太网利用率达30%即为重载
{% endnote %}

{% note default %}
**【作业题】** 有两台主机A和B接在800m长的电缆线两端，t=0时各自向对方发送一个帧，帧长度为1500bit。A和B之间有4个转发器，转发时产生20bit时延。传输速率为100Mbit/s，CSMA/CD退避时间中争用期为512bit。发生第一次碰撞后，A选择r=0，B选择r=1。信号传播速率2×10⁸ m/s。忽略人为干扰信号和帧间最小间隔。

（1）计算从A到B（包括4个转发器）的传播时间。

（2）在什么时间B完全收到A发送的帧？

（3）若4个转发器都用交换机代替，交换机存储转发时额外产生20bit处理时延，B完全收到A帧的时间？

**解答：**

（1）电缆传播时延 = 800/(2×10⁸) = 4μs

4个转发器时延 = 4×(20/10⁸) = 0.8μs

从A到B总传播时延 = 4 + 0.8 = **4.8μs**

（2）A的发送时延 = 1500/(100×10⁶) = 15μs

争用期 = 512/(100×10⁶) = 5.12μs

第一次碰撞发生在t≈4.8μs，A选择r=0退避0个争用期，等待5.12μs后重发。A重发时不会再碰撞。

总时延 = 第1次发送到碰撞停止 + 等待空信道 + 第2次发送 + 第2次传播

= 4.8 + 5.12 + 4.8 + 15 + 4.8 ≈ **29.4μs**

（3）用交换机替代转发器后：

每个交换机需要存储转发，额外时延 = 转发时延(20bit) + 处理时延(20bit) = 40bit

总时延 = A的发送时延 + 电缆传播时延 + 4个交换机转发时延

= 15 + 4 + 4×(15 + 0.2) = **79.8μs**
{% endnote %}

### 3.5 以太网MAC层

**MAC帧格式（以太网V2）：**
| 字段 | 长度 | 说明 |
|------|------|------|
| 前同步码 | 7字节 | 10交替，实现比特同步 |
| 帧开始定界符 | 1字节 | 10101011 |
| 目的地址 | 6字节 | MAC地址 |
| 源地址 | 6字节 | MAC地址 |

| FCS | 4字节 | CRC校验 |

- **有效帧长度：64~1518字节**（不含前同步码和帧开始定界符）
- 数据字段最小46字节（64-18首尾），不足需填充
- MAC地址48位 = 6字节，全球唯一（OUI+厂商自分配）

### 3.6 扩展以太网与设备对比

{% note primary %}
**重点：集线器、网桥、交换机的异同**

| 设备 | 工作层次 | 特点 |
|------|----------|------|
| **转发器/中继器** | 物理层 | 连接不同网段，消除信号衰减失真 |
| **集线器** | 物理层 | 多端口转发器，所有端口共享总线带宽，广播域 |
| **网桥** | 数据链路层 | 根据MAC帧目的地址转发和过滤，分割冲突域 |
| **以太网交换机** | 数据链路层 | 多接口网桥，全双工，同时连通多对端口，自学习建立帧交换表，独占带宽无碰撞 |

**交换机自学习算法：**
1. 收到帧 → 查找帧中源地址在交换表中的项目
   - 无→新增（源地址、进入接口、有效时间）
   - 有→更新
2. 查找帧中目的地址在交换表中的项目
   - 无→向除进入接口外所有接口广播（泛洪）
   - 有且接口不同→按表转发
   - 有且接口相同→丢弃
{% endnote %}

**【作业题】** 以太网交换机连接的局域网，各主机IP和子网掩码（255.255.255.240）：

A: 192.168.1.35，B: 192.168.1.50，C: 192.168.1.46，D: 192.168.1.60，E: 192.168.1.46

（1）哪些计算机之间可以直接访问？哪些不能？为什么？

**解答：**

（1）掩码255.255.255.240（/28），子网按16个地址分块：

- A(35)和E(46)的子网地址 = 192.168.1.32（32~47）
- B(50)、C(46)、D(60)的子网地址 = 192.168.1.48（48~63）

（2）换为集线器后，**情况会变**——集线器不能分隔子网，所有计算机处于同一物理网段，它们之间都可以直接访问。
{% endnote %}

### 3.7 虚拟局域网VLAN

- 由一些局域网网段构成的与**物理位置无关**的逻辑组
- 限制了接收广播的计算机数量，防止**广播风暴**
- VLAN标记放在MAC帧源地址字段和类型字段中间（**4字节**），成为802.1Q帧
- 最大帧长从1518字节变为1522字节

### 3.8 真题与解答

{% note default %}
**【真题】IEEE802.3局域网传递ASCII信息封装MAC，计算帧有效字节，需要填充多少字节？**

若数据部分为n字节：
- 帧最小长度 = 64字节 = 首部(14字节) + 数据 + FCS(4字节)
- 数据最小 = 64 - 14 - 4 = 46字节
- 若n < 46，需填充 46 - n 字节
- 若n ≥ 46，不需要填充

**【真题】10BASE-T争用期51.2μs，报文重传三次后，用截断二进制指数退避算法计算再次准备重传最多需要等待的时间？**

第4次重传，重传次数=4，$k = \min(4, 10) = 4$
从 $\{0, 1, 2, ..., 2^4-1\} = \{0,1,2,...,15\}$ 中取最大值r=15
最多等待时间 = $15 \times 51.2\mu s = 768\mu s$
{% endnote %}

### 4.2 子网划分与子网掩码

{% note danger %}
**必考点：子网掩码计算、最大主机数、地址块、路由聚合**

**子网掩码作用：** 将IP地址与子网掩码进行"与"运算，得到网络地址（子网地址）

**划分子网步骤：**
1. 确定需要的子网数和每个子网的主机数
2. 从主机号中借用高位作为子网号
3. 计算子网掩码
4. 注意：子网中主机号全0全1的地址不可指派（即可用主机数 = $2^m - 2$，m为主机号位数）

**CIDR（无分类域间路由）：**
- 地址格式：a.b.c.d/n（n为网络前缀长度）
- CIDR中的子网号可以全0全1，但主机号不能全0全1
- 路由聚合（超网）：将多个小地址块合并为一个大地址块
- **最长前缀匹配：** 查找路由表时选择网络前缀最长的匹配项
{% endnote %}

{% note default %}
**【作业题】** 某公司拥有/22地址块，用变长子网掩码划分子网。6个部门主机数：A=500，B=250，C=120，D=60，E=25，F=12。

（1）为每个部门划分子网并写出子网掩码。

（3）为什么非空子网的子网掩码不可以是255.255.255.254？

### 4.4 IP数据报分片

{% note danger %}
**必考点：IP数据报分片计算（每年必考）**

**标志字段（3位，只有后2位有意义）：**

| 位 | 名称 | 含义 |
|----|------|------|
| 最高位 | 保留 | 必须为0 |
| 中间位 | **DF (Don't Fragment)** | DF=**1** → **禁止分片**，路由器不能对该数据报分片，若超出MTU则丢弃并返回ICMP差错报文；DF=**0** → **允许分片** |
| 最低位 | **MF (More Fragment)** | MF=**1** → **后面还有分片**（不是最后一片）；MF=**0** → **这是最后一片**（或未分片） |

**片偏移（13位）：** 表示该分片的数据部分在原始数据报中的起始位置，单位为**8字节**。例如片偏移=185，表示该片从原始数据的第 185×8=1480 字节开始。

**分片规则：**
- 每个分片数据长度必须是**8字节的整数倍**（因为片偏移单位为8字节）
- 除最后一个分片外，MF=1；最后一个分片MF=0
- 每个分片都有完整IP首部，且**标识字段相同**
- DF=0才允许分片
{% endnote %}

{% note default %}
**【真题】数据报总长度4820字节，首部20字节，数据4800字节。网络最大传输长度1420字节，如何分片？**

每个分片可用数据 = 1420 - 20 = 1400字节
1400 / 8 = 175（整数，满足8字节整数倍）

| 分片 | 数据长度 | 总长度 | MF | DF | 片偏移 |
|------|---------|--------|----|----|--------|
| 1 | 1400 | 1420 | 1 | 0 | 0 |
| 2 | 1400 | 1420 | 1 | 0 | 175 |
| 3 | 1400 | 1420 | 1 | 0 | 350 |
| 4 | 600 | 620 | 0 | 0 | 525 |

类似上题思路，PPP帧MTU=1500字节：
- 数据部分最大 = 1500 - 20 = 1480字节，1480/8=185（整数）
- 分片1：数据1480，总长1500，MF=1，偏移=0

| 3 | 1020 | 2960/8 = **370** | **0** |
{% endnote %}

### 4.5 ARP协议

{% note primary %}
**重点：ARP工作原理和四种典型使用情况**

**ARP作用：** 将IP地址转换为物理（MAC）地址

**工作过程：**
1. 查ARP高速缓存 → 有则直接使用
2. 无则广播发送ARP请求分组
3. 目的主机收到后单播返回ARP响应分组
4. 更新ARP高速缓存（设生存时间TTL）

**ARP四种典型情况：**
1. 主机 → 本网络主机：ARP找目的主机硬件地址
2. 主机 → 另一网络主机：ARP找本网络路由器硬件地址
3. 路由器 → 本网络主机：ARP找目的主机硬件地址
4. 路由器 → 另一网络主机：ARP找下一跳路由器硬件地址
{% endnote %}

### 4.6 ICMP协议

- 属于网际层协议（**不是高层协议**）
- ICMP报文装在IP数据报的数据部分中
- **差错报告报文：** 终点不可达、时间超过、参数问题、改变路由（重定向）
- **询问报文：** 回送请求/回答、时间戳请求/回答
- **不应发送差错报告报文的情况：** 对ICMP差错报告报文本身、后续数据报片、组播/特殊地址的数据报

### 4.7 路由选择协议

#### RIP协议（距离向量/内部网关协议）

{% note warning %}
**重点：RIP路由表更新算法、坏消息传得慢**

**RIP特点：**
- 仅和**相邻路由器**交换信息
- 交换的是自己完整的路由表
- 按固定时间间隔交换
- 距离度量=**跳数**（最大15跳，16=不可达）
- 使用**UDP**传送
- **好消息传播快，坏消息传得慢**（收敛时间长）

**距离向量算法：**
收到地址X的相邻路由器发来的RIP报文后：
1. 将所有项目的距离+1，下一跳改为X
2. 若原路由表无该目的网络 → 添加
3. 若原路由表有该目的网络，且原下一跳=X → 替换
4. 若原路由表有该目的网络，且原下一跳≠X，新距离更小 → 更新
5. 3分钟未收到更新 → 标记不可达(16)
{% endnote %}

{% endnote %}

**【作业题】** 一个数据报分组交换网允许节点必要时丢弃分组。设节点丢弃概率为P。一个主机经过2个网络节点与另一主机通信，共3段链路。只要任何节点丢弃分组，源点重传。试问：

（1）每个分组一次传输中平均经过几段链路？

（2）每个分组平均要传送几次？

（3）目的主机每收到一个分组，连同被丢弃的传输，平均需经过几段链路？

**解答：**

（1）从源主机到目的主机共3段链路：

- 经过1段（源→节点1）概率 = p
- 经过2段（源→节点1→节点2）概率 = (1-p)p
- 经过3段（源→节点1→节点2→目的）概率 = (1-p)²

$$\text{平均链路段数} = 1 \cdot p + 2 \cdot (1-p)p + 3 \cdot (1-p)^2$$

化简后得：$\frac{3 - 2p + 2p^2}{1 - p + p^2}$

（2）一次成功的概率 α = (1-p)²，需多次发送，平均传送次数 = 1/α = 1/(1-p)²

（3）每个分组平均传送次数×平均链路段数
{% endnote %}

### 5.1 运输层概述

### 5.3 UDP协议

### 5.4 TCP协议

{% note primary %}
**重点：TCP报文段格式、三次握手四次挥手、可靠传输、拥塞控制**

**TCP特点：**
- 面向连接、可靠交付、全双工通信、面向字节流
- 每条TCP连接只能有两个端点（点对点）

**TCP报文段首部（固定20字节）：**
| 字段 | 长度 | 说明 |
|------|------|------|
| 源端口 | 2字节 | |
| 目的端口 | 2字节 | |
| 序号 | 4字节 | 本报文段数据第一个字节的编号 |

| RST | 1位 | 重置连接 |
| **SYN** | **1位** | **同步序号，建立连接时使用** |

| 窗口 | 2字节 | 接收窗口，允许对方发送的数据量 |
| 检验和 | 2字节 | |

{% note default %}
**【作业题】** 假定用TCP协议在40Gbit/s线路上传送数据：

（1）TCP充分利用带宽，多长时间发生序号绕回？

（2）TCP首部采用时间戳选项（4字节，32位），每859微秒加1，多少时间发生时间戳绕回？

**解答：**

（1）TCP序号32位，共 $2^{32}$ 个序号。充分利用40Gbps：

绕回时间 = $2^{32} \times 8 / (40 \times 10^9)$ = 4294967296×8/(40×10⁹) ≈ **0.859s = 859ms**

（2）时间戳32位，每859μs加1：

绕回时间 = $2^{32} \times 859 \times 10^{-6}$ = 4294967296 × 859μs ≈ **3689377s ≈ 42.7天**
{% endnote %}

{% note default %}
**【作业题】** 主机A向B连续发送两个TCP报文段，序号分别为70和100：

（1）第一个报文段携带了多少字节？

（2）B收到第一个报文段后确认号应为多少？

（3）B收到第二个报文段后确认号为180，第二个报文段有多少字节？

（4）如果第一个报文段丢失但第二个到达，确认号应为多少？

**解答：** TCP序号是所载数据第一个字节的编号，确认号=收到的连续数据最后字节编号+1。

（1）100-70 = **30字节**

（2）**100**（期望收到的下一个字节编号）

（3）180-100 = **80字节**（编号100~179）

（4）第一个丢失，B只收到100~179，确认号仍为**100**（累积确认，期望从70开始重传）
{% endnote %}

### 5.5 TCP三次握手与四次挥手

{% note warning %}
**必考点：三次握手和四次挥手的状态转换**

**三次握手（建立连接）：**
1. 客户 → 服务器：**SYN=1, seq=x**（客户端进入SYN-SENT状态）
2. 服务器 → 客户：**SYN=1, ACK=1, seq=y, ack=x+1**（服务器进入SYN-RCVD状态）
3. 客户 → 服务器：**ACK=1, seq=x+1, ack=y+1**（双方进入ESTABLISHED状态）

**四次挥手（释放连接）：**
1. 客户 → 服务器：**FIN=1, seq=u**（客户进入FIN-WAIT-1）
2. 服务器 → 客户：**ACK=1, seq=v, ack=u+1**（服务器进入CLOSE-WAIT，客户→服务器方向已释放，**半关闭**）
3. 服务器 → 客户：**FIN=1, ACK=1, seq=w, ack=u+1**（服务器进入LAST-ACK）
4. 客户 → 服务器：**ACK=1, seq=u+1, ack=w+1**（客户进入TIME-WAIT，等待**2MSL**后进入CLOSED）
{% endnote %}

### 5.6 TCP可靠传输

{% note primary %}
**ARQ（自动重传请求）三种协议对比：**

| 对比项 | 停止等待 ARQ（Stop-and-Wait） | 回退N帧 ARQ（GBN，Go-Back-N） | 选择重传 ARQ（SR，Selective Repeat） |
|--------|-------------------------------|-------------------------------|---------------------------------------|
| **发送窗口** | 1 | n（n > 1） | n |
| **接收窗口** | 1 | 1 | n |
| **确认方式** | 逐个确认 | 累积确认 | 逐个确认 |
| **出错处理** | 超时重传该帧 | 超时则回退，**重传该帧及其后所有已发帧** | 只**重传出错的那一帧** |
| **信道利用率** | 最低 | 较高 | 最高 |
| **接收端缓存** | 不需要 | 不需要 | 需要缓存乱序帧 |
| **复杂度** | 最简单 | 中等 | 最高 |
{% endnote %}

{% note default %}
**【作业题】** TCP协议如何保证可靠传输？

**解答：**

（1）应用数据分割成TCP认为最适合发送的数据块

（2）TCP对每个数据块编号，接收方确认

（3）TCP首部有检验和字段，检测传输中的变化

（4）接收方有缓存和流量控制（滑动窗口），防止丢失

（5）TCP使用可变大小滑动窗口实现流量控制

（6）拥塞控制：网络拥塞时减少数据发送

（7）停止等待协议：每发一个分组就等待确认

（8）超时重传：发送后启动定时器，未及时收到确认则重发
{% endnote %}

{% note warning %}
**信道利用率计算（重要）：**

> 发送方从发送第一个比特开始，到收到确认为止为一个发送周期。一个周期中只有发送数据的那段时间在做有用工作，其余时间都在等待，因此：

**1. 停止等待协议（发送窗口=1）：**

$$U = \frac{T_D}{T_D + RTT + T_A}$$

- $T_D$：发送一个分组的时间（= 分组长度/发送速率）
- $RTT$：往返时延
- $T_A$：确认帧发送时间（通常远小于 $T_D$，可忽略）
- 利用率很低，大部分时间在等待确认

**2. 连续ARQ / 回退N步协议（滑动窗口，发送窗口=n）：**

$$U = \frac{n \cdot T_D}{T_D + RTT + T_A}$$

- n 为发送窗口大小（一次可连续发送的分组数）
- 当 $n \geq 1 + RTT/T_D$ 时（即发送窗口 ≥ **信道容量/带宽时延积**），发送方可连续发送不中断，$U \approx 1$（利用率达到100%）
- 窗口越大利用率越高，但受接收窗口和网络拥塞限制

**对比理解：** 停止等待是 n=1 的特例。滑动窗口通过批量发送将等待时间"重叠"掉，从而大幅提升利用率。
{% endnote %}

{% note default %}
**【作业题】** 假定要在网络上传送1.5MB文件，分组长度1KB，RTT=80ms。建立TCP连接时间=2×RTT=160ms。计算接收方收完最后一个比特的时间：

（1）数据发送速率10Mbit/s，可连续发送。

（2）速率10Mbit/s，每发完一个分组后要等一个RTT。

（3）速率极快忽略发送时间，每个RTT只能发20个分组。

（4）速率极快，第1个RTT发1个，第2个RTT发2个，第n个RTT发2ⁿ⁻¹个。

**解答：** 1.5MB = 1.5×2²⁰ = 1572864字节，每分组1KB，共 1572864/1024 = **1536个分组**。发送时延 = 8×1.5×2²⁰/(10×10⁶) ≈ 1.258s。传播时延 = 40ms。

（1）总时延 = TCP连接时延 + 发送时延 + 传播时延 = 160 + 1258.29 + 40 = **1458.29ms**

（2）1536个分组有1535个等待间隔（最后一个无需等待），总时延 = 160 + 1258.29 + 1535×80 + 40 ≈ **124258.29ms = 124.26s**

（3）每RTT发20个，需1536/20 = 76.8，即77批（76整批+最后一批16个），总时延 = 160 + 76×80 + 40 = **6280ms = 6.28s**

（4）第n个RTT结束共发送1+2+4+...+2ⁿ⁻¹ = 2ⁿ-1个分组。n=10时共1023个，剩余513个在第11个RTT发送。总时延 = 160 + 10×80 + 40 = **1000ms = 1s**
{% endnote %}

### 5.7 TCP超时重传时间计算

{% note warning %}
**必考点：RTTs和RTO计算**

**加权平均往返时间：** $RTT_S = (1-\alpha)(旧RTT_S) + \alpha(新RTT样本)$
- 推荐α=1/8

**RTT偏差加权平均值：** $RTT_D = (1-\beta)(旧RTT_D) + \beta|RTT_S - 新RTT样本|$
- 推荐β=1/4

**超时重传时间：** $RTO = RTT_S + 4 \times RTT_D$

**注意：** 报文段重传时不采用其往返时间样本
{% endnote %}

{% note default %}
**【真题】已知：旧的RTTs=30ms，新的RTT样本=26ms，旧RTT_D=5ms，α=1/8，β=1/4。求新RTTs和新RTO。**

$RTT_S = (1 - 1/8) \times 30 + 1/8 \times 26 = 7/8 \times 30 + 1/8 \times 26 = 26.25 + 3.25 = 29.5$ ms

$RTT_D = (1 - 1/4) \times 5 + 1/4 \times |29.5 - 26| = 3.75 + 0.875 = 4.625$ ms

$RTO = 29.5 + 4 \times 4.625 = 29.5 + 18.5 = 48$ ms
{% endnote %}

{% note default %}
**【作业题】** RTT当前值30ms，随后应答分别在26、32、24ms到来，α=0.9。计算新RTT估算值。

**解答：** $RTT_S = \alpha \times RTT_{S旧} + (1-\alpha) \times RTT_{样本}$

$RTT_1 = 0.9 \times 30 + 0.1 \times 26 = 27 + 2.6 = $ **29.6ms**

$RTT_2 = 0.9 \times 29.6 + 0.1 \times 32 = 26.64 + 3.2 = $ **29.84ms**

$RTT_3 = 0.9 \times 29.84 + 0.1 \times 24 = 26.856 + 2.4 = $ **29.256ms**
{% endnote %}

{% note default %}
**【作业题】** TCP建立连接时RTO=6s：

（1）收到连接确认报文段，RTT样本值1.5s，计算RTO。

（2）发送数据报文段收到确认，RTT样本值2.5s，计算RTO。

**解答：**

（1）初次测量：$RTT_S(1) = 1.5s$，$RTT_D(1) = RTT(1)/2 = 0.75s$

$RTO(1) = 1.5 + 4 \times 0.75 = $ **4.5s**

（2）$\alpha = 0.125$，$\beta = 0.25$（RFC6298）

$RTT_S(2) = (1-0.125) \times 1.5 + 0.125 \times 2.5 = 1.625s$

$RTT_D(2) = (1-0.25) \times 0.75 + 0.25 \times |1.625 - 2.5| = 13/16 = 0.8125s$

$RTO(2) = 1.625 + 4 \times 0.8125 = $ **4.875s**
{% endnote %}

### 5.8 TCP流量控制与拥塞控制

#### 流量控制

- 通过**滑动窗口**机制实现，让发送方发送速率不要太快
- 发送窗口不超过接收窗口大小
- **糊涂窗口综合征：** 接收方缓存满→应用每次读1字节→窗口设为1字节→效率极低
  - 解决：接收方等待缓存有足够空间再发送确认

#### 拥塞控制

{% note danger %}
**必考点：拥塞窗口cwnd变化、慢开始、拥塞避免、快重传、快恢复**

**四种算法：**

| 算法 | 触发条件 | cwnd变化 | ssthresh变化 |
|------|----------|----------|-------------|
| **慢开始** | cwnd < ssthresh | 每个RTT**加倍** | 不变 |
| **拥塞避免** | cwnd ≥ ssthresh | 每个RTT**加1** | 不变 |
| **超时** | 检测到超时 | cwnd=**1**，执行慢开始 | ssthresh = cwnd/2 |
| **快重传+快恢复** | 收到**3个重复确认** | cwnd = **ssthresh**（=原cwnd/2） | ssthresh = cwnd/2 |

**关键公式：**
- $cwnd \leq ssthresh$ → 慢开始（指数增长）
- $cwnd \geq ssthresh$ → 拥塞避免（线性增长）
- **超时：** $ssthresh = cwnd/2$，$cwnd = 1$，重新慢开始
- **3个重复ACK：** $ssthresh = cwnd/2$，$cwnd = ssthresh$，快恢复
{% endnote %}

{% note default %}
**【真题】ssthresh初始值为8，cwnd上升到12时发生超时，求第1~15次传输cwnd值：**

### 6.1 域名系统DNS

{% note primary %}
**重点：域名解析过程、递归与迭代查询、DNS高速缓存**

**域名结构：** 树状层次结构（根域→顶级域→二级域→...)

**域名服务器分类：**
| 类型 | 说明 |
|------|------|
| 根域名服务器 | 最高层，知道所有顶级域名服务器地址 |
| 顶级域名服务器 | 管理所有二级域名 |
| 授权域名服务器 | 每台主机登记处的服务器 |
| 本地域名服务器 | 主机首先查询的服务器 |

**域名解析两种方式：**

| 方式 | 过程 |
|------|------|
| **递归查询** | 主机→本地域名服务器，本地服务器代为完成后续查询，最终返回IP或报错 |
| **迭代查询** | 本地→根→顶级→授权，每一步返回下一级服务器地址，本地服务器自行逐级查询 |

**通常：** 主机向本地域名服务器用**递归**，本地域名服务器向其他服务器用**迭代**

**DNS高速缓存的作用：**
- 缓存最近查询的域名到IP地址映射
- 减少DNS查询的网络流量
- 加快域名解析速度
- 设置生存时间TTL，到期自动删除
{% endnote %}

{% note default %}
**【真题】访问域名，迭代查询，本地域名服务器最多最少发几个DNS请求？**

假设需要查询 www.example.com：
- 本地向根服务器发送1次请求 → 获得顶级域名服务器地址
- 本地向顶级域名服务器发送1次请求 → 获得授权域名服务器地址
- 本地向授权域名服务器发送1次请求 → 获得IP地址

**迭代查询最少发3个DNS请求**（根→顶级→授权各一次）

**如果是递归查询**：主机只需向本地域名服务器发1个请求，本地服务器代劳
{% endnote %}

### 6.2 文件传输协议FTP

{% note info %}
**FTP特点：**
- 使用**TCP**可靠传输
- **控制连接**（端口21）：传输FTP命令（持久连接）
- **数据连接**（端口20）：传输文件内容（每次传输后关闭）
- 服务器由主进程+从属进程组成
- 主进程负责接受新请求，从属进程处理单个请求
{% endnote %}

**FTP与TFTP区别：**
| 对比项 | FTP | TFTP |
|--------|-----|------|
| 传输协议 | TCP | UDP |
| 可靠性 | 高 | 低 |
| 功能 | 完整文件传输 | 简单文件传输 |
| 连接 | 控制连接+数据连接 | 单一连接 |

{% note default %}
**【作业题】** 简述FTP的工作过程，为什么FTP的控制信息是带外传送的？

**解答：**

FTP工作过程：服务器端主进程打开**端口21**（熟知端口），等待客户端连接请求。当有连接请求到达时，主进程启动从属进程（控制进程），建立**控制连接**处理请求，主进程继续监听其他请求。控制连接持续存在。当需要传输文件时，创建另一个从属进程（数据进程），建立**数据连接**（端口20），传输完毕后关闭数据连接。

FTP使用分离的控制连接和数据连接，因此控制信息是**带外传送**的（控制信息与数据分开传输）。
{% endnote %}

### 6.3 万维网WWW与HTTP

{% note warning %}
**重点：HTTP请求方法、HTTP/1.0与1.1区别、HTTP无状态**

**HTTP（超文本传送协议）：**
- 面向事务的应用层协议
- 基于**TCP**，服务器监听**端口80**
- **无状态**：服务器不保留客户的状态信息
  - 好处：简化服务器设计，减轻服务器负担
  - 坏处：无法跟踪用户行为

**HTTP请求方法：**
- **GET：** 请求读取URL所标识的资源（获取页面）
- **POST：** 向URL标识的资源附加数据（提交表单）
- HEAD：获取报文首部
- PUT：存储资源
- DELETE：删除资源

**HTTP/1.0 vs HTTP/1.1：**

| 对比项 | HTTP/1.0 | HTTP/1.1 |
|--------|----------|----------|
| 连接方式 | **非持续连接** | **持续连接** |
| 每次请求文档 | 建立TCP连接→请求→释放 | 复用同一TCP连接 |
| 开销 | 2倍RTT + 传输时间 | 节省RTT |
| 流水线 | 无 | 支持（不等响应就发下一个请求） |

**请求一个文档时间：** 2RTT + 文档传输时间（HTTP/1.0非持续连接）

**URL格式：** `<协议>://<主机>:<端口>/<路径>`
{% endnote %}

{% note default %}
**【作业题】** 假定在浏览器上点击一个URL，IP地址未缓存。需经过n个DNS服务器解析，时间分别为RTT₁、RTT₂、...、RTTₙ。从本地主机到网页的往返时间为RTTₘ：

（1）只需读取一个小图片（忽略传输时间），从点击到显示共需多长时间？

（2）若使用非持续HTTP（不并行），读取4个对象需要多长时间？

（3）若使用并行TCP连接的非持续HTTP？

（4）若使用流水线方式的持续HTTP？

**解答：**

（1）DNS解析（迭代）需 $RTT_1 + RTT_2 + ... + RTT_n$，TCP建立+请求+响应需 2×RTTₘ

**总时间 = RTT₁ + RTT₂ + ... + RTTₙ + 2×RTTₘ**

（2）非持续不并行HTTP：每对象需建立TCP+请求+响应=2×RTTₘ

DNS + 1个主页(2RTTₘ) + 3个小对象(各2RTTₘ) = **RTT₁+...+RTTₙ + 8×RTTₘ**

（3）并行TCP非持续HTTP：3个小对象同时传输

= **RTT₁+...+RTTₙ + 4×RTTₘ**（DNS + 主页2RTTₘ + 建立并行连接1RTTₘ + 并行传输1RTTₘ）

（4）流水线持续HTTP：一个TCP连接传输所有内容

= **RTT₁+...+RTTₙ + 3×RTTₘ**（DNS + TCP建立+主页2RTTₘ + 流水线传输所有1RTTₘ）
{% endnote %}

### 6.4 SMTP、POP3与IMAP

{% note primary %}
**重点：SMTP三阶段通信、POP3与IMAP区别**

**SMTP（简单邮件传送协议）：**
- 基于**TCP**，端口**25**
- **推（Push）协议**：发送方发送
- **三个通信阶段：**
  1. **连接建立：** 客户与服务器TCP连接，服务器发送220 Ready
  2. **邮件传送：** HELO→MAIL FROM→RCPT TO→DATA→邮件内容→.（结束）
  3. **连接释放：** QUIT

**POP3（邮局协议第3版）：**
- 基于**TCP**，端口**110**
- **拉（Pull）协议**：接收方读取
- **下载并删除**方式：邮件下载到本地后从服务器删除
- **下载并保留**方式：邮件下载后在服务器上保留副本

**IMAP（网际报文存取协议）：**
- 端口**143**
- 邮件保留在服务器上，用户可以在服务器上管理邮件（创建文件夹、标记等）
- 支持按内容搜索邮件

**POP3 vs IMAP：**
| 对比项 | POP3 | IMAP |
|--------|------|------|
| 连接方式 | 断开后不再操作邮件 | 持续在线操作 |
| 邮件管理 | 下载到本地 | 在服务器上管理 |
| 文件夹支持 | 不支持 | 支持 |
| 搜索 | 不支持 | 支持内容搜索 |
{% endnote %}

### 6.5 DHCP协议

{% note warning %}
**重点：DHCP工作过程（四步）**

**DHCP（动态主机配置协议）：** 即插即用连网，自动分配IP地址

**DHCP工作过程：**
1. **发现（DISCOVER）：** 客户从UDP端口68**广播**发送（目的IP=255.255.255.255，源IP=0.0.0.0）
2. **提供（OFFER）：** 服务器从UDP端口67**广播/单播**回应，提供IP地址等配置
3. **请求（REQUEST）：** 客户选择其中一个服务器，发送请求报文
4. **确认（ACK）：** 服务器确认，IP地址绑定完成

**租用期管理：**
- T1 = 0.5T（租用期过半时请求续租）
- T2 = 0.875T（服务器不响应时再次请求）
- 到期仍未续租→释放IP地址，重新申请
{% endnote %}

{% note default %}
**【作业题】** DHCP协议用在什么情况下？当一台计算机第一次运行引导程序时，其ROM中有没有IP地址、子网掩码或DNS服务器地址？

**解答：**

DHCP（动态主机配置协议）用于主机加入新网络时自动获取IP地址等配置信息，实现**即插即用连网**。除普通主机外，还可用于无盘工作站。

计算机第一次运行引导程序时，其ROM中**没有**IP地址、子网掩码或DNS服务器地址——这些是通过软件配置的逻辑地址（软件地址）。只要网络上有DHCP服务器，计算机就可以通过广播方式发送发现报文，由DHCP服务器单播提供报文，从而获得IP地址等配置信息。
{% endnote %}

### 6.7 MIME

**MIME（多用途互联网邮件扩展）：** 解决SMTP只能传送ASCII文本的限制，使电子邮件可以传送各种非文本数据（图像、音频、视频等）。在邮件首部增加MIME-Version、Content-Type等字段。

{% note default %}
**【作业题】** 假设数据为：110011001000000100111000

（1）对该数据进行Base64编码，得出传送的ASCII数据是什么？编码开销多大？

（2）如对该数据进行quoted-printable编码，得出的ASCII数据是什么？编码开销多大？

**解答：**

（1）Base64编码步骤：

① 24位划分为4个6位组：

`110011` `001000` `000100` `111000`

② 查表：110011(51)→z，001000(8)→I，000100(4)→E，111000(56)→4

**Base64编码 = zIE4**

编码开销 = 4/3 - 1 ≈ **33.3%**

（2）quoted-printable编码：前两个字节是汉字（非ASCII），需转换；第三个字节是ASCII字符8不变。

第一字节 11001100 → 十六进制 **CC**，第二字节 10000001 → 十六进制 **81**

**编码结果 = =CC=818**（每个非ASCII字节→等号+两位十六进制）

编码开销 = 6/3 - 1 = **100%**（原3字节变6字节）
{% endnote %}

### 6.8 真题与解答

{% note default %}
**【2024春回忆版】本网络没DHCP服务器如何配置主机网络？**
需要**手动配置**：IP地址、子网掩码、默认网关、DNS服务器地址

**【真题】HTTP/1.0无状态的含义和好处？**
- 含义：服务器不保留关于客户的状态信息，每个请求独立处理
- 好处：简化服务器设计，减轻服务器存储和管理负担，提高可扩展性

**【真题】对于一个具体域名写出迭代解析过程。**
1. 主机向本地域名服务器发送查询请求
2. 本地域名服务器向**根域名服务器**发送查询请求
3. 根域名服务器返回对应的**顶级域名服务器**地址
4. 本地域名服务器向顶级域名服务器发送查询
5. 顶级域名服务器返回**授权域名服务器**地址
6. 本地域名服务器向授权域名服务器发送查询
7. 授权域名服务器返回**IP地址**
8. 本地域名服务器将IP地址返回给主机
{% endnote %}

{% note default %}
**【作业题】** 下图表示各应用协议在层次中的位置：

（1）为什么有的应用层协议用TCP，有的用UDP？

（2）为什么MIME画在SMTP之上？

（3）为什么路由选择协议RIP放在应用层？

**解答：**

（1）TCP面向连接、可靠；UDP无连接、尽最大努力、不可靠。需要可靠性的应用用TCP（如HTTP、FTP、SMTP），需要实时性和简单的应用用UDP（如DNS、RIP、DHCP）。使用UDP的协议可靠性可由应用层自身编码实现。

（2）SMTP是基础邮件传输协议，**MIME是SMTP的扩展**，将非ASCII邮件转换成ASCII后用SMTP传输。MIME使用SMTP，是SMTP的更高层，而非替代SMTP。

（3）RIP需要定时与相邻路由器交换路由表信息，该信息封装在**UDP数据报**中。RIP报文是不同路由器上进程间交换信息的单位，因此被放在**应用层**。
{% endnote %}
